# FinDocRAG 当前问题审计与优化优先级

审计范围：回答生成、检索路由、PDF 处理、上传链路、UI 交互、评测和工程可运行性。

## P0：必须立即修复

### P0-1 回答生成源文件中文编码损坏

- 现象：`src/findoc_rag/answer_generation.py` 中拒答文案、季度指标、提示词和表格输出出现 `褰撳墠`、`缁忚惀` 等乱码。
- 影响：用户看到乱码；季度抽取条件无法稳定匹配；发送给 DeepSeek 的 system prompt 语义失真；面试演示不可接受。
- 根因假设：文件曾被以错误编码读写，导致 UTF-8 中文被二次转码。
- 修复方案：以 UTF-8 重写中文常量和 prompt，增加中文回答回归测试，并禁止非 UTF-8 文件进入源码。
- 验收标准：三个真实问题返回可读中文；拒答和季度表格抽取测试稳定通过。

### P0-2 `/v1/query` 未自动应用公司和年份过滤

- 现象：`SearchRequest.filters` 只有用户显式传入时才生效。
- 影响：查询“贵州茅台 2024 年……”时可能召回伊利或其他公司的相似章节，LLM 会在错误证据上生成流畅答案。
- 修复方案：从 query 推断公司名和 `20xx` 年份，与显式 filters 合并；冲突时以显式过滤为准并记录 trace。
- 验收标准：真实三问的 evidence 公司、年份与问题一致；跨公司证据触发拒答。

### P0-3 远程 LLM 输出没有二次证据校验

- 现象：只要 HTTP 请求成功就标记 `grounded=true`，没有检查回答是否引用 `[1]` 或是否包含证据外数字。
- 影响：DeepSeek 可能返回未被证据支持的数字，系统却把答案标为 grounded。
- 修复方案：强制引用格式；校验引用编号、回答中的关键数值和 evidence；失败时返回 guardrail-abstention。
- 验收标准：错误引用、无引用和证据外数字均不能标记 grounded。

## P1：近期必须完成

### P1-1 PDF 上传只有落盘，没有解析和建索引任务

当前 `/v1/uploads` 返回 `uploaded` 后没有后台 ingest/index 阶段，UI 的上传功能容易被误解为“上传即可问”。需要 job 状态机、错误信息和索引版本回写。

### P1-2 表格结构仍然是线性文本

季度指标目前依赖文本顺序猜测四个数字，缺乏列标题、单位、合计校验。应保存表格区域、行列坐标、单位和抽取置信度，并为跨页表格建立回归样例。

### P1-3 UI 证据和 trace 展示缺少契约测试

前端依赖后端字段名，当前应增加 API fixture 驱动的浏览器级 smoke test，覆盖示例问题、空结果、拒答、上传失败和证据折叠。

### P1-4 评测集仍偏小且 provisional

16 条问题适合作为回归集，不足以支持业务效果结论。应按公司、年份、问题类型和表格/叙述分层扩充，并保留人工复核记录。

## P2：产品化增强

- 增加索引版本切换和实验 diff UI。
- 增加延迟、token 成本、拒答率和跨公司污染率指标。
- 对 OCR、扫描件和页眉页脚异常建立独立质量门禁。
- 将 trace 中的敏感 query 做脱敏和 retention 策略。
- 让 README 与实际启动脚本、端口冲突处理和 DeepSeek 配置完全一致。

## 建议实施顺序

```text
修复编码 -> 公司/年份路由 -> LLM 证据校验
-> 上传任务状态机 -> 表格结构恢复 -> UI 契约测试
-> 扩充分层评测集 -> 实验对比和成本指标
```
