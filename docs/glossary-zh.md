# 术语表

带 `等宽字体` 的是代码和数据文件里的真实字段名，改不了，但正文尽量用中文说。

## 评测集结构

| 术语 | 说人话 |
|---|---|
| **问法类型**（`query_regime`） | 同一道题的不同问法。分三类，见下 |
| **原题**（`canonical`） | 照年报原文措辞提的问题，如"贵州茅台 2024 年营业收入是多少" |
| **代码简称问法**（`ticker_or_finance_shorthand`） | 用股票代码或财务简称提问，如"600519 2024 年营收"。ticker = 股票代码 |
| **口语问法**（`semantic_or_relative_time`） | 换种说法或用相对时间，如"去年营收"、"毛利水平怎么样" |
| **变体**（`query_variants`） | 由原题改写出的另一种问法。48 道原题各配 2 个变体 = 96 个变体 |
| **题组**（`family`） | 同一个考点派生的一组题。同组题不能分散到不同 split，否则等于泄题 |
| **提问时点**（`as_of_date`） | 冻结的"今天是哪天"。评测里"去年"必须按这个日期算，不能用系统当前时间，否则分数会随运行日期漂移 |

## 答案与证据

| 术语 | 说人话 |
|---|---|
| **标准答案 / 正确证据**（gold） | 人工确认过的正确答案，或确认包含答案的那段原文 |
| **原子事实** | 把一个答案拆成不可再分的小项：数值、单位、期间、口径各算一项，逐项核对 |
| **干扰段落**（hard negative） | 从真实年报里挑的、和正确答案长得很像但用错了地方的段落。五类：错公司、错期间、错口径、证据不全、因果硬凑 |
| **近失拒答** | 资料里确实有数字，但答的不是你问的（口径或期间不对），系统应该说"我不确定"而不是硬答 |
| **口径** | 同一个指标的不同统计范围，如合并 vs 母公司、扣非 vs 归母。年报里最容易混的一类歧义 |
| **切片**（`chunk`） | 文档被切开后的一小段，是检索的最小单位 |
| **来源可追溯**（provenance） | 每个答案都能回到具体文档、页码、章节、切片和原始元素 |
| **Document IR** | PDF 解析后的中间表示，保留页码、元素坐标、阅读顺序。IR = intermediate representation |

## 三条评测赛道

同一批题给不同的上下文，用来定位错误出在哪一层。赛道在代码里叫 `lane`。

| 赛道 | 给什么上下文 | 测什么 |
|---|---|---|
| **直接给答案**（`oracle_context`） | 只给正确证据 | 生成能力的上限。这都答不对，问题就不在检索 |
| **真实检索**（`retrieved_context`） | 走完整检索链路 | 端到端真实水平 |
| **抗干扰**（`robustness`） | 正确证据里混入干扰段落 | 会不会被"长得很像"的段落骗到 |

对比即定位：直接给答案好、真实检索差 → 检索或路由的问题；直接给答案也差 → 生成或表格抽取的问题；只有抗干扰掉 → 容易被干扰污染。

## 指标

| 术语 | 说人话 |
|---|---|
| **Hit@5** | 前 5 个结果里有没有正确证据。只看"有没有" |
| **Recall@5** | 前 5 个结果找回了多少比例的正确证据。每题只有一段证据时，和 Hit@5 数值相同 |
| **Precision@5** | 前 5 个结果里有多少比例是相关的 |
| **MRR@5** | 第一个正确结果排在第几位（越靠前越高）。Hit@5 相同但 MRR 不同，说明排序质量有差别 |
| **NDCG@5** | 考虑位置的排序质量综合分 |
| **候选池召回**（`candidate_recall`） | 正确证据有没有进入候选池。用来区分"根本没捞到"和"捞到了但排序排砸了" |
| **全对率**（`strict_success`） | 一道题的所有原子事实全部正确才算过。比"答对一部分"严格得多，所以分数看着低 |
| **行为准确率**（`behavior_accuracy`） | 该答的答了、该拒的拒了、该问的问了 |
| **可计分**（`eligible`） | 该题符合这个指标的计分条件。叙述类答案不进确定性全对率，改由语义评测负责 |
| **部分判定**（partial-judgment） | 只有干扰段落被标为负例，语料里其余段落未标注。所以全语料的 Precision / NDCG 是下界，必须注明 |

## 检索与融合

| 术语 | 说人话 |
|---|---|
| **关键词检索**（BM25 / `lexical`） | 按词匹配打分。对公司名、会计科目这类专有名词很稳 |
| **语义检索**（dense） | 把句子转成向量比相似度。对换种说法更宽容，但对长句和专业改写容易失效 |
| **混合检索**（hybrid / RRF） | 把两路结果合并。RRF 按排名倒数加权，`2:1` 指关键词路权重是语义路的两倍 |
| **权重扫描**（sweep） | 把权重按 3:1、4:1 等挨个试一遍，看哪个最好 |
| **元数据过滤**（metadata filter） | 按公司、年份先筛掉无关文档，再检索 |
| **口径路由**（scope routing） | 识别问题问的是季度/分部/合并/母公司/附注，据此调整排序 |
| **重排**（rerank） | 用更贵的模型把候选结果重新排一遍 |

## 门禁与纪律

| 术语 | 说人话 |
|---|---|
| **一票否决**（fail closed） | 任一硬检查不过就直接中止，不允许"带着警告继续跑" |
| **冻结**（frozen） | 数据定版后不能原地改。要改就出新版本，否则前后分数没法比 |
| **答案泄漏**（leakage） | 用正确答案帮忙过滤或筛选，等于作弊。用了就不能算正式成绩 |
| **伪重复** | 同一道题的 3 种问法当成 3 个独立样本，会虚高样本量。做法是先按原题聚合再平均 |
| **judge 独立性**（`independent_judge`） | 打分模型和答题模型是不是同一个。同一个就是自己给自己打分，只能当辅助诊断 |
| **`independent_gold: false`** | 标准答案是助手自审的，没有第二人独立复核。所以不能对外主张准确率 |
| **版本钉** | 一次实验用的数据集版本、索引版本、配置版本。结论必须带这三个，否则无法复现 |
