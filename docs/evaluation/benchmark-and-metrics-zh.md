# FinDocRAG 评测规则：数据集、指标与门禁

> 本文档只写**规则**：数据集怎么构造、指标怎么定义、门禁怎么判定、报告怎么写。这些内容在实验之间保持稳定。
> 每轮实验的**数字**（基线、薄弱点、待办）见 [baseline-zh.md](./baseline-zh.md)；改进计划见 [improvement-list-zh.md](./improvement-list-zh.md)。
> 看不懂的词见 [术语表](../glossary-zh.md)。带 `等宽字体` 的是代码和数据里的真实字段名。

## 1. 评测集如何建立

```text
评测集（题目 + 正确证据 + 答案要求）
├── 检索赛道：该答的题 —— 正确证据为正例，干扰段落为负例
└── 行为赛道：该拒答的题 + 该追问的题
        ├── 直接给答案（oracle_context）：只给正确证据，测生成上限
        ├── 真实检索（retrieved_context）：走完整链路，测端到端
        └── 抗干扰（robustness）：正确证据里混入干扰段落
```

1. **证据锚定**：PDF → 解析成中间表示 → 切片，定位正确切片、页码、原文引用、章节路径
2. **事实拆分**：拆成原子事实（数值 / 单位 / 期间 / 口径）；直接给出的数值必须出现在绑定的原文引用里；需要算的事实要记公式
3. **题目生成**：按考点分组；同一考点、同一段证据的题不能分散到不同数据划分，否则等于泄题
4. **干扰标注**：干扰段落必须来自真实年报，不能编。五类：错公司、错期间、错口径、证据不全、因果硬凑
5. **答案要求**：期望行为（该答 / 该拒 / 该追问）+ 格式 + 引用和单位要求
6. **变体生成**：每题 2 个变体（股票代码 / 财务简称 / 相对时间 / 口语改写），相对时间的题必须冻结提问时点
7. **校验与冻结**：程序门禁 + 首次 100% 人工审核，然后冻结，不许原地改

## 2. 三条评测赛道

| 赛道 | 给什么上下文 | 测什么 |
|---|---|---|
| **直接给答案**（`oracle_context`） | 只给正确证据 | 生成和回答策略的上限 |
| **真实检索**（`retrieved_context`） | 走真实检索 + 路由 + 证据门禁 | 端到端系统 |
| **抗干扰**（`robustness`） | 正确证据之间插入错公司 / 错期间 / 错口径 / 证据不全 / 因果硬凑的段落；该拒答的题也给诱导性证据 | 会不会被"长得很像"的段落骗到 |

三条一对比就能定位错误在哪层：直接给答案好、真实检索差 → 检索或路由的问题；直接给答案也差 → 生成、表格解析或提示词的问题；只有抗干扰掉 → 容易被高相似干扰污染。

## 4. 指标定义

### 检索侧

取前 K 个结果来算（当前 K=5）：

| 指标 | 含义 |
|---|---|
| **Hit@K** | 前 K 个里有没有正确证据。只看有没有，不看几个 |
| **Recall@K** | 前 K 个找回了多少比例的正确证据 |
| **Precision@K** | 前 K 个里有多少比例是相关的 |
| **MRR@K** | 第一个正确结果排在第几位（越靠前分越高）。Hit 相同而 MRR 不同，说明排序质量有差别 |
| **NDCG@K** | 考虑位置的排序质量综合分。当前只区分"相关 / 不相关"两档，将来可以扩成分级 |
| **候选池召回**（`candidate_recall`） | 正确证据有没有进候选池。用来区分"根本没捞到"和"捞到了但排序排砸了" |
| **平均证据量**（`avg_evidence_tokens_top5`） | 前 K 条结果的切片估算 token 均值。反映"把多少证据送进下游"的上下文预算 |

注意：过去报告里的 Hit@5 只表示"至少命中一个"，不等于严格的 Recall@5。当前每题通常只有一段正确证据，所以两者数值相同；等有了多段证据的题，二者会自然拉开。

检索失败分四类：正确证据没进候选池 / 进了候选池但被融合挤下去 / 过滤条件把它排除了 / 文档根本没解析出来。

### 生成侧（确定性指标，机器判定）

行为准确率、全对率、事实召回率、数值准确率、单位准确率、引用有效性、上下文召回率、拒答与追问准确率、报错率。

### 上下文效率与延迟（每个实验同时报告）

| 指标 | 含义与口径 |
|---|---|
| **`avg_context_tokens`** | 每次生成实际送进 LLM 的上下文估算 token 均值（取前 5 条切片、每条截断 1800 字符，用项目自己的 `estimate_tokens` 估算）。回答"为了答对一题，喂了多少上下文" |
| **`p95_latency_ms`** | 单次生成/检索延迟的 95 分位。长上下文主要影响 prefill / 首 token 延迟与 KV cache 占用，RAG 压缩上下文会同时改善成本、延迟与 serving 容量 |

定位：这是 RAG 的**工程价值之一**（context efficiency / token efficiency），不是替代准确率的定义。长上下文提高的是"一次能消费的信息上限"，RAG 解决的是"哪些信息值得进入上下文"——从大规模语料中筛选最小但充分的证据集，在保持准确率与可追溯性的同时降低 input token 和推理成本。

后续实验目标：在 strict success 不下降的前提下压缩 `avg_context_tokens`，并画 Accuracy–Token Pareto Frontier。

### 生成侧（语义指标，模型判定）

用 RAGAS 跑四项：答案有没有编（faithfulness）、答案切不切题（answer relevancy）、给的上下文相不相关（context relevance）、上下文有没有覆盖答案所需信息（context recall）。

该拒答的题不计入"有没有编"的均值，否则大量拒答就能把分数刷高。

如果打分模型和答题模型是同一个（都用 DeepSeek），产物必须记录 `independent_judge=false`。自己给自己打分只能当辅助诊断，不能用来覆盖数值、单位、公司、年份、口径、引用这些硬门禁的判定。

### 失败归因

每题只归一个主因，按最早那个不可挽回的环节判定：检索 → 上下文选择 → 生成 → 行为。次要问题可以多选。多事实的题归到具体哪个事实上。

## 5. 评分策略

1. **该答的题**：按正确切片计 Hit@K / Recall@K / MRR
2. **该拒答的题**：评有没有捞到假证据、有没有正确拒答，不给它伪造一个"正确答案"
3. **该追问的题**：评有没有识别出歧义并追问，不计入检索得分
4. **Precision / NDCG**：只有干扰段落被标为负例，语料里其余段落没标注。所以全语料的 Precision / NDCG 是下界，必须标注"部分判定"，除非补做完整标注
5. **变体问句**：先按原题聚合再求总平均。同一道题的三种问法不是三个独立样本，直接平均会让带变体的题权重过高

## 6. 防答案泄漏

每份评测报告必须记录四件事：有没有开元数据过滤、过滤条件从哪来、用了哪些字段、这次是不是诊断性运行。

过滤条件来源共六种：不过滤、从问句解析、用户显式指定、**从正确答案的元数据来**、**从正确答案来**、其他。后两种等于用答案帮忙筛选，报告会被校验器拒绝，不能算正式成绩。压根没记录来源的直接判无效。

运行校验：

```bash
python scripts/validate_eval_report.py your-report.json
```

## 7. 数据门禁（一票否决）

硬检查，任一项不过就直接中止评测并抛 `BenchmarkIntegrityError`：

- 每条记录都绑定索引版本和切片格式版本；正确切片必须 100% 存在
- 原文引用必须 100% 能在切片里匹配上（空白和换行的归一化规则固定）
- 变体结构、提问时点、公司、年份必须一致
- 评测配置必须 100% 完整落盘，包含过滤条件来源
- 冻结数据被原地修改 → 拒绝

软检查只发警告，不中止：人工审核覆盖率、变体多样性、PDF 复核待办。

改动切片逻辑会让版本门禁不通过，从而强制你重新锚定证据或出一个新版本评测集。这是故意的——不允许悄悄覆盖，否则改动前后的分数就没法比了。

## 8. 语义评测的范围校验

语义评测不假定每次运行都包含数据集全部该答的题，而是先确认这次跑的是哪条赛道，再取"这条赛道实际跑了哪些题"与"数据集里该答的题"的交集：

- **直接给答案**和**真实检索**必须完整包含当前 48 题，少一条或混进未知的题，在调用打分模型之前就会失败
- **抗干扰**必须精确包含带干扰段落的那 29 题；其中 18 条该答，所以语义评测覆盖率是 `18 / 37`
- 以下情况都在发出远程请求之前失败：题号重复、题号不在数据集里、数据集版本对不上、索引版本对不上、运行时报过错、赛道范围不符、答案与证据结构自相矛盾
- **实际行为与答案要求不一致，算模型答得不好，不算产物坏了。** 答错的、该答却拒答的、该拒答却硬答的，全部保留在计分集合里，只是额外记一份"行为不符"的题号清单。如果因为答错就中止或剔掉样本，就会只剩答对的进评测，分数虚高——这叫幸存者偏差

输出保存的审计字段：运行 ID、赛道、口径策略、数据集题数、数据集该答题数、赛道题数、赛道该答题数、实际跑的条数、可计分条数、覆盖率、赛道内覆盖率、行为不符题号，以及运行 / 赛道 / 可计分 / 已排除的完整题号清单。每行结果都回填题号，方便和确定性分数、失败案例逐题对照。

两个覆盖率的分母不同：**覆盖率**用数据集全部 37 道该答题当分母，用来横向比较三条赛道谁覆盖得广；**赛道内覆盖率**用这条赛道自己的该答题当分母，用来证明这次运行没在赛道内漏题。抗干扰赛道的正常值分别是 `18/37` 和 `1.0`。

示例（抗干扰赛道）：

```powershell
.venv\Scripts\python.exe scripts\run_ragas_generation_eval.py `
  reports\generation\runs\robustness-generation-eval-v1-b7f4d6113c96-deepseek-chat\items.jsonl `
  --output reports\generation\ragas-robustness-b7f4d6113c96.json
```

## 9. 防作弊与统计纪律

- 每份报告必须记录过滤条件来源；用正确答案帮忙过滤的报告不能当正式成绩
- 同一考点的题不跨数据划分；冻结数据不能原地改；来源 JSON 和 PDF 全部用 SHA-256 锁定
- 变体先按原题聚合再平均，防止"变体多就等于样本多"
- 没有全量标注的 Precision 必须标"部分判定"
- 置信区间和第二人独立复核还没做，在计划里（见改进清单 P3）

## 10. 结论边界

现在这套东西可以称为：**证据经过原文核验、带受控干扰、有三条赛道的中文财务 RAG 冻结回归集原型**。

但因为只有两家公司、一个年份，标准答案也没有第二人独立复核，**不能**称为跨文档泛化能力的证明，也不能称为生产级 benchmark。
