## 每个增量解决了什么

### P1-A：跨页结构提取

`search_evidence` 先定位表格锚点，`get_page_window` 再按锚点的 `document_id` 展开有限相邻
页，永不跨文档。DeepSeek 最终从第 185–186 页、章节 `二、累计折旧` 的 chunk 提取
`3,316,847,042.37`，没有误取同名“账面原值期末余额合计”。

P1-A0 已经检索到正确证据，但模型一次并行展开三个窗口，旧工具历史又诱导最终轮继续
搜索，结果被本地门禁拒绝。P1-A1 只执行一个窗口，并在提交前建立仅含任务和 Evidence
Memory 的新上下文；输入 token 从 41,263 降到 27,602，同时新增题通过。

### P1-B：带来源的受控计算

DeepSeek 不负责心算，只选择三个 `value + evidence_chunk_id` 操作数。本地门禁先确认每个
数字原样存在于所引 chunk，再用 `Decimal` 执行：

```text
9,158,716,606.73 - 3,316,847,042.37
= 5,841,869,564.36
勾稽差额 = 0.00
```

三个数分别引用第 185–186 页的三个 chunk。P1-B0 暴露了 DeepSeek 并行工具调用未全部
回填时的协议错误；P1-B1 将检索、页面窗口、计算三阶段彻底隔离后通过。

### P1-C：视觉关系按需升级

权益结构图的扁平文本保留名称和百分比，却丢失连线关系。`inspect_page_region` 仅在该类
任务触发，并执行四层门禁：

1. 锚点必须来自当前检索结果，页码必须落在锚点页范围；
2. `document_key` 只能解析到来源 manifest 中的本地 PDF，并校验 SHA-256；
3. 从 PDF 原生文字层提取节点与 bbox，按纵向中心配对左侧标签和百分比；
4. 只有中间存在 PDF 绘图线段的关系才交给 DeepSeek确认，本地再求和。

最终重建 `H股股东→17.00%`、`国家能源投资集团有限责任公司→69.52%`、
`其他A股股东→13.48%`，本地合计 `100.00%`，引用固定在第 306 页。

## 当前命令能力

- `compare`：跨公司、跨年度、口径和重述比较；
- `extract`：单份年报中的跨页表精确抽取；
- `calculate`：当前支持带来源的减法勾稽和权益结构图百分比求和；
- `inspect`：只读已持久化的完整任务轨迹。

当前仍不是通用自治 Agent：任务类型和工具预算有界，计算器只接受已实现的受控操作，视觉
工具使用原生 PDF 几何而非通用视觉模型；扫描页、复杂合并单元格和任意图表仍需单独评测。
