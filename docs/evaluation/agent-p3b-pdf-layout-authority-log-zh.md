# Agent hard-v3 P3-B：PDF 页级版面重建与权威来源排序

## 结论

P3-B 完成。系统不再默认相信 PDF 自带文字层，也不再把“最先检索到的页”等同于“最适合
引用的页”：

- 对关键审计事项，先把锚点页及一页续页渲染为图像，再按左右栏分别 OCR 和重建阅读顺序；
- 对多指标抽取、核验和可比口径问题，扩大候选后优先选择财务摘要、关键指标、业绩综述、
  主要经营业绩、内含价值分析等权威汇总页；
- 只有候选页确实包含回答中的数值，并且来源权威分更高，才允许补充该页为引用。

最终组合报告中，48 题严格通过率由 **43/48（89.58%）提升到 45/48（93.75%）**，
净增 2 题、4.17 个百分点。校准集 22/24 保持不变，开发集从 21/24 提升到 23/24。
安全拒答、澄清、任务覆盖和引用完整率均保持 100%。本阶段没有修改 Gold、评分器、索引
或 frozen test。

## 为什么不能只做“全量 OCR”

工商银行 2023 年报第 197 页的可见内容是双栏审计程序，但 PDF API 读出的文字块却是与
页面不相干的目录文本；这是错误/陈旧隐藏文字层，不只是普通双栏乱序。整页 OCR 又会把
左右两栏同一高度的文本交错合并。

因此采用按需、页级、分栏的回退链路：

1. 正常页面继续使用原生文字层和已有索引；
2. 只有“关键审计事项/审计应对/审计程序”类抽取任务触发版面重建；
3. 来源 PDF 必须在 manifest 白名单中且 SHA-256 一致；
4. 锚点最后一页和一页续页分别渲染；
5. 左、右半页独立 OCR，过滤低置信行后按列顺序合并；
6. 重建内容形成带文件哈希、页码和内容哈希的合成 evidence ID，进入 Evidence Memory；
7. DeepSeek 只接收这两页的重建文本，不接收整份 PDF。

这条路径处理的是“文字层不可信”和“列顺序错误”；普通原生文本页不会无条件重复 OCR。

## 权威来源排序

原检索结果可能先命中董事长致辞、分部章节或同指标的非目标口径页面。P3-B2 增加了三层
约束：

- 查询层：多指标抽取和核验任务先搜索财务摘要/关键指标及目标口径，再补 requirement
  缺口；
- 排序层：按章节权威性、问题要求的指标、集团/可比/调整后口径和数值覆盖综合排序；
- 引用层：若现有答案数值没有出现在更权威候选页，不得为了“看起来权威”而挂该引用。

这不是让 DeepSeek 自由判断来源可信度；候选检索、数值存在性检查、分数比较和引用 ID
合法性都由本地代码执行。

## 评测结果

| 数据集 | P3-A 严格通过 | P3-B 严格通过 | P3-A 事实准确率 | P3-B 事实准确率 |
|---|---:|---:|---:|---:|
| calibration | 22/24（91.67%） | 22/24（91.67%） | 91.35% | 92.31% |
| dev | 21/24（87.50%） | 23/24（95.83%） | 97.17% | 97.17% |
| 合计 | 43/48（89.58%） | 45/48（93.75%） | — | — |

严格修复的两题：

- `v3_601318_y23_core`：集团核心指标的引用从非权威/不覆盖 Gold 页，修复为覆盖财务摘要页；
- `v3_601318_verify_nbv`：内含价值核验补入目标权威页，citation source coverage 从 0 到 1。

校准集工商银行 ECL 审计题的机器 exact 从 6/13 提升到 7/13。逐页人工复核后，当前回答的
13/13 个事实均能在引用页找到；其余 6 个机器未命中是词面差异，例如“敞口/暴露”、
“多宏观情景及权重/经济情景及情景权重”和“抵质押物/抵押物”。没有为这道题修改评分器，
因此它仍按 7/13 计分，也没有被包装成严格通过。

## 成本

最终用于组合的定向运行共：

- DeepSeek 请求 89 次；
- 输入 token 301,570；
- 输出 token 33,735；
- 合计 token 335,305；
- 检索/页面工具调用 110 次。

包含截断、校验失败和 post-hoc 修复在内的全部 P3-B 实验共 1,710,229 token。这个总成本
用于暴露失败模式，不代表单次线上任务成本。生产运行只会对命中的复杂页做两页重建。

## 负实验与治理说明

- P3-B1 calibration v1/v2 的原子事实清单输出达到 2,048 token 上限，被本地门禁安全拒答；
  后续压缩候选 schema 并限制清单规模，失败报告仍保留。
- P3-B2 calibration v3 中，模型同时提交 `requirement_id` 和 `requirement_ids`，严格 schema
  导致一题拒答；解析器现只容忍这一种常见的单复数字段冗余，其他未知字段仍拒绝。
- 首次 dev 抽取分别暴露未知候选 ID 和主体口径标签过度逐字校验；修复后才得到最终
  post-hoc v3。开发集结果不是无偏确认。
- frozen test 始终封存；下一次无偏确认必须在该集上一次性运行，不能继续依据开发集调参。

## 尚未解决

- 工商银行 ECL 审计题仍受 exact 同义词评分限制，严格结果没有提升；
- 中国平安审计题仍为 14/17，说明页级 OCR 解决“内容进不来”，但不能保证模型完整枚举；
- 当前分栏策略针对稳定的左右双栏，不覆盖三栏、旋转文本、跨栏表格和任意扫描件；
- 权威章节权重是可解释启发式，后续应以独立标注的 claim-source 对训练/评测，而不是继续
  用当前开发集微调；
- 需要在仍封存数据上报告文档层 bootstrap 区间，当前 +2 题不能外推为通用 PDF 能力。
