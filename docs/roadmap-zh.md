## 1. 当前完成度

FinDocRAG 是面向中文上市公司年报的可追溯 RAG：PDF → 按结构切片 → 版本化索引 → 检索 → 口径路由 → 带证据门禁的回答，外加一套可复现的双层评测体系。

- **评测基础设施 ✅** 评测集定版、数据集完整性门禁、配置强制落盘、相对时间锚定——评测本身可信、可复现、防泄漏
- **A 阶段检索定论 ✅** 变体矩阵、融合权重扫描、同义词改写、OOV + LLM 改写、中文 dense 对照：canonical 默认 lexical-only + deterministic，生产自由文本可选带质量门控的 LLM 改写
- **DeepSeek 最终三轨 ✅** 同 migration / index / code fingerprint 下 Oracle / Retrieved / Robustness strict 与行为均 1.0、error 0；Retrieved 37/37 gold context；RAGAS 完整覆盖但为 DeepSeek 自评
- **B 阶段冻结范围闭环 ✅**：PDF IR v2、真实 PDF/IR 双输入 154/157、安全候选 Precision/Recall 98.1%、15 表 / 195 cells index-bound sidecar 与在线结构路由；剩余是 OCR 缺字与更大盲测
- **Agent 准备层已完成第一版**：稳定 query/capabilities/evidence-resolve 契约、证据哈希与 claim-citation；C 行为 / 时间对齐和 D 公信力仍继续

一句话现状：**当前冻结集已形成“PDF→索引绑定结构证据→路由→回答→审计”的完整闭环；下一阶段不再追当前集分数，而是用独立 judge、多公司多年度和扫描件盲测验证外部有效性。**

## 2. 三个战略问题

### 2.1 语义检索到底该不该用、怎么用

评测揭示的不是"语义模型弱"这么简单：同一个模型在"股票代码 / 简称"这类问法上能到 0.676，在原题和口语问法上只有 0.2 左右。说明**问句的形态**（长度、指代是否唯一）的影响远大于模型本身。

**权重扫描已做完并给出定论**（fusion-sweep-v1）：只用关键词检索、完全不掺语义检索，在三种问法上都碾压任何融合权重（Hit@5 0.838 / 0.811 / 0.730）。逐问法挑最优也全都选"不掺"，说明按问法动态选路在当前模型下没有增益。给语义路任何正权重都是拖累。

**2026-08-11 对照已做完**：换中文专用小模型（bge-small-zh-v1.5）在三种问法和 OOV 上全面退化（dense 0.083–0.568，均低于 E5），证明当前 dense 失败的主因不是"中文/多语言模型能力"，而是问句形态 + 上游表格线性化。同时 OOV 评测证明 **LLM 查询改写是词表外问法的决定性杠杆**（lexical Hit@5 0.194 → 0.694）。剩下的问题：bge-m3 等更大模型在表格结构化之后能否补上语义路，届时用同一套扫描重新验证融合，而不是继续盲调。

**另一个上游因素（已确认）**：PDF 表格线性化（数字与标签分离、行列关系丢失）让语义检索的输入以"数字密集的无结构文本"为主，进一步放大了表面相似度误导（实测语义检索最常召回"关联交易–存款业务"这类无关数字表格）。**决策：暂用关键词检索（已落地），B 阶段表格结构化完成后，与更强语义模型一起用同一套扫描重新验证**——届时模型能力与信息提取质量可以分离归因。

**术语处理三层架构（新 PDF 可扩展性的答案）**：

1. **查询侧**：LLM 查询改写把用户口语归一化为通用财务术语（不依赖具体文档，新 PDF 不需要改）；
2. **文档侧**：指标知识库 + ingest 时 LLM 术语归一化，把不同文档的同一概念（销售收入 / 营业收入）打到同一概念 ID——这是查询改写解决不了的层，因为 LLM 不知道新文档用什么措辞；
3. **快速兜底**：确定性词表只放高频确定改写，不是机制。

验证机制：**OOV（词表外改写）评测**验证查询侧；**document-blind 评测**（未见过的新公司 / 新年度）验证两层组合在真实新文档上有效。单纯靠手工扩词表不是可扩展方案，这条边界已明确写入设计。

### 2.2 表格结构化：核心能力已验证，下一步扩覆盖

早期直接把正确证据摆在眼前也只有 0.31；确定性表格接入后 no-LLM Oracle 提升到 0.6571，证明它确实是生成侧的大杠杆。当前已完成五类文本抽取、单元格坐标重建、列头对齐、跨页隔离、单位与原文一致性门禁，并让 PDF 与持久化 IR v2 在 157-cell 尺子上得到相同的 154/157。结构结果已作为 15 表 / 195 cells 的 index-bound sidecar 被在线问答和三轨评测共同消费。下一步不是继续针对这两份年报调规则，而是用扫描件、多公司、多年度盲测验证泛化。

### 2.3 时间与口径语义：从 demo 到领域产品的分水岭

年报特有的歧义：去年 / 前年（时间锚点在哪）、合并 vs 母公司（口径）、扣非 vs 归母（口径）、已实施 vs 预案（时点）。评测已经证明这些问题真实存在（时间对齐的 bug 已复现）。做好这一层，系统才能回答"什么时候该答、什么时候该追问、什么时候该拒"——这正是 Agent 的核心能力。

## 3. 阶段顺序

| 阶段 | 内容 | 预期收益 | 验收 |
|---|---|---|---|
| **A. 检索定论**（✅ 完成，2026-08-12 软收尾） | 权重扫描定论 + 默认策略 lexical-only + 同义词改写 + OOV 评测 + LLM 查询改写 + bge-zh dense 对照 + 生产 /v1/query 接入（缓存/回退）+ **改写质量门控** + **路由错误率指标** | **口语问法 Hit@5 0.73 → 0.92；OOV 0.194 → 0.694；bge-zh 无收益**；路由评测 18/18 精确匹配；门控劣化自动回退 | A 全部收官；下一主战场 B（表格）/ C（行为） |
| **B. 表格重建**（✅ 冻结范围闭环） | 文本抽取 + IR v2 坐标重建 + chunk-grounded 安全选择 + index-bound sidecar + schema-aware routing | 坐标 raw 154/157、165 pred → safe 154/157、157 pred；最终三轨 strict / 行为均 1.0 | OCR 或视觉模型处理文字层真实缺字；多公司盲测 |
| **C. 时间与行为** | 时间对齐落地 + 追问题扩到约 12 条 + 补 5–8 组多轮对话 | 时间错配归零；行为准确率可测 | 清单 P2-15 / P1-8 / P1-9 完成 |
| **D. 公信力** | 再加 2 家公司 × 1–2 个年度，整份文档留出做盲测；冻结集扩到 24+ 并人工复核；换独立打分模型；给分数加置信区间 | 分数可以对外主张 | 清单 P3 全部完成 |

A 是快赢（1–2 天）并能立刻提供"融合策略修正"的完整故事；B 决定项目上限；C 决定 Agent 叙事；D 决定数字能不能对外主张。

| 时间错配导致正确证据被过滤掉的已知用例 | ✅ 0/1（原 `yili_2025_plan_bounded` 已修，并有 runner/API 回归） | 扩展多年度后保持 0 |
| 真实检索赛道的平均生成上下文（`avg_context_tokens`） | ≈1536（2026-08-07 基线） | 在 strict success 不下降的前提下压缩（Pareto 实验） |

> 目标数字是方向性估计，不是承诺；每一格都要通过冻结集配对对比验证之后再更新。

> **RAG 的工程价值定位**：长上下文提高的是"模型一次能消费的信息上限"，RAG 解决的是"哪些信息值得进入上下文"。对大规模企业知识库，把全部文档直接塞给模型既有 token 成本和延迟问题，也会引入无关证据和口径干扰（同一份年报里营业收入、主营业务收入、母公司/合并口径并存）。RAG 本质是 query-aware context compression：筛选最小但充分的证据集，在保持准确率和可追溯性的同时降低 input token 与推理成本。指标已落地：`avg_context_tokens` / `p95_latency_ms` / `avg_evidence_tokens_top5`。

## 6. 已经能讲的故事与最大风险

能讲的（见 [面试说明](./interview/findoc-rag-interview-guide-zh.md)）：

- **评测工程** —— 识别出系统偏关键词检索、96 个专业变体问句、真实年报干扰段落、防泄漏门禁
- **数据驱动归因** —— 用"直接给答案 0.31 vs 真实检索 0.09"定位检索瓶颈；发现语义检索只在股票代码问法上有效这个反常现象
- **工程严谨性** —— 一票否决的门禁、配置快照、迁移清单、防止同题多问法虚高样本量

最大风险，按严重度：

1. **标准答案是自审的** —— 必须补第二人独立复核，才能对外主张准确率
2. **样本量太小** —— 2 家公司 1 个年度，任何数字都要带边界声明
3. **当前满分可能掩盖覆盖不足** —— 表格 sidecar 已进入在线默认链路，但冻结集只有两家公司/一年；必须用整份新文档盲测防止规则对当前版式过拟合
4. **扫描件/OCR 未形成真实盲测** —— 当前两份年报都有可用文字层，不能外推到扫描 PDF
